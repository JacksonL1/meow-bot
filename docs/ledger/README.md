# 开发台账

这个目录记录 `clawd-starter` 的开发情况：**每个文件做什么、每个阶段做到哪、每阶段有什么安全问题、踩了什么坑。**

放这里而不是单独一个笔记软件，是因为它跟代码一起走：换电脑、回滚、开新会话，AI 都能直接读到，不用你复述背景。

## 文件说明

| 文件 | 记什么 | 什么时候看 |
|---|---|---|
| `PROJECT.md` | 项目定位、阶段路线、技术栈、启动方式、硬约束 | 开工前 / 隔久了回来 |
| `PROGRESS.md` | 当前目标、各阶段待办勾选、按阶段汇总的安全状态 | 每天开工第一眼看 |
| `SECURITY.md` | 分阶段安全问题（现状 10 条 + SEC-11 + S4/S5/S6 落地核对 + S7 预判） | **每个阶段开工前和收工时** |
| `FILE_MAP.md` | 每个文件的职责、阶段归属、数据流图 | 改代码前找入口 |
| `GLOSSARY.md` | 技术名词手册：40+ 个名词，每个都能指到具体行 + 速查卡 + 自测 20 题 | 复习 / 讲给别人听之前 |
| `DEVLOG.md` | 踩坑与心得，只追加 | 遇到诡异问题时先搜这里 |
| `scripts/check-filemap.js` | 巡检：找出「代码里有、台账里没记」的文件 | 定期 / 加文件后 |
| `scripts/daily-check.js` | 每日体检：对比 git / 文件 / 依赖 / 漏洞的增量，无变化时明确输出「不用更新」 | 每天自动跑，也可手动 |

## 怎么用

**对你**：每天开工看 `PROGRESS.md` 的「当前目标」；动手改代码前，如果碰的是安全相关的地方，先翻 `SECURITY.md` 对应阶段。

**对 AI**：在这个项目里工作时，按以下规则维护台账。

1. 完成一个阶段或一个功能点 → 在 `PROGRESS.md` 打勾，并在「变更时间线」加一行。
2. 新增/删除/改名文件 → 更新 `FILE_MAP.md` 对应条目（不要重写整张表）。
3. **每完成一个阶段，必须过一遍 `SECURITY.md` 的「阶段检查清单」**，把结论回写到该阶段小节。安全和功能一起算完成。
4. 踩了坑 → 追加到 `DEVLOG.md` 顶部，五段式：场景 / 现象 / 原因 / 解法 / 教训。
5. 不确定的写 `TODO`，不要凭文件名猜职责。

## 三条底线

- **安全不是收尾工作**。S5 的权限回包只要有一条没做对，就是把 Claude Code 的权限确认机制开了后门——这种「先做出来再补安全」在权限类功能上是不成立的。
- **时间线只追加不回改**，避免覆盖之前手写的内容。
- **台账的价值在于活着**。写完就再没人看的文档不如不建，所以宁可少记，也要保证每次都真的更新。
