## 看板：DSH headless 历史收进折叠分组

- 用户问「看板 56 条、DSH 客户端只有 5 条」：看板列磁盘全量投影，其中 46 条是 `dsh headless` 一次性残留（多数是我们自己的验证跑出来的），客户端只展示交互会话。
- 改法：DSH 组里非活跃且 `has_stats === false`（headless 不写 sessionStats，宿主既有字段）的会话归进「历史一次性会话（N 条）」折叠行；`toggleHeadless()` 用 `lastRender` 缓存同步重渲染；活着的会话永不折叠，折叠组里是完整卡片（可续聊）。
- 踩坑：把渲染循环重构成 nodes 数组 append 时弄丢了 `g.more.remove()`，残影行留在 DOM 且排在卡片前面，两条旧闸门当场红——常驻节点的撤出责任不跟卡片走。
- 验证：UI 闸门 162 → 166，166 PASS / 0 FAIL。注意：用户桌宠在跑时，测试实例要设 `WEBVIEW2_USER_DATA_FOLDER` 隔离，否则 WebView2 0x8007139F 起不来。
- 文档：README、PROGRESS、PROJECT（硬约束 59）、FILE_MAP、DEVLOG 已同步。

## 写锁竞争：按操作的租约，常是瞬时的

- 用户报「另一个 dsh 正开着这条会话」，但客户端没开那条、桌宠没在跑、终端没有 dsh。查桌面版 `app.asar` 的 `dsh-session-persistence-jsonl/lease`：租约 = 会话目录 `session.lock` + 内核独占锁，桌面端打开/加载/收尾补写都会短暂持有，写句柄关即释放；DSH 撞 `EAGAIN` 直接抛错，不重试。
- 改法：`say::CONTENDED_MSG` + `is_contended()`，`say_send` 撞上后 1.5s 自动重试一次；文案改为「等一两秒再发，反复出现才关掉那条会话」。
