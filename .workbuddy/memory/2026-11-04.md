## DSH 数据面：两条读取通道（已实测）

1. **投影缓存** `~/.dsh/storages/session_projcache.json`（约 6KB，纯 JSON，无需解压）
   `tables.sessions.<id>` 下有 `identity`（createdAt/cwd）、`title`、`sessionStats`、`tokenUsage`、`goal`。
   `sessionStats` 含 `turns / steps / openStep / pendingCalls`——**`openStep !== null` 即"正在干活"**，`null` 即空闲。这是桌宠状态机最省事的上游信号。

2. **会话日志** `~/.dsh/sessions/<slug>/<session-id>/session.v4.jsonl.zstd`
   - 是 **多帧 zstd**（append-only 每次追加一个 frame）。`zlib.zstdDecompressSync` 只解第一帧，必须按 magic `28 B5 2F FD` 切帧逐帧解。实测 14095 字节 → 42 帧 → 85 行。
   - 每行是事件，带单调递增 `seq` 与 `time`（ms），可只读增量。
   - 事件类型实测：`session` / `turn/start` / `turn/end` / `step/start` / `step/end` / `user/message` / `assistant/message` / `assistant/chunk` / `reasoning-chunks` / `text-chunks` / `session/title` / `command/run` / `command/done` / `agent/inbox/spliced` / `request/header` / `request/context` / `permission/preset` / `sandbox/mode` / `approval/policy` / `agent-preset/selected`。
   - `TurnEndReason.kind` 枚举：`completed` / `aborted` / `interrupted` / `error`（插件可扩展）。

## DSH 写入面：可代为发送，且有回执（已实测）

`dsh --profile headless --session-id <id> "消息"` —— **adopt 已有 session，发一个新 turn**。

实测证据（同一 sessionId，turn 1 → 2）：
```
{"type":"session","sessionId":"session-ec2c73c8-...","cwd":"E:\\..."}
{"type":"status","phase":"turn_start","turn":2}
{"type":"status","phase":"step_start","turn":2,"step":1}
{"type":"status","phase":"turn_end","turn":2,"reason":{"kind":"error","error":{...}}}
{"type":"final","text":""}
```
回执三件套：退出码（成功 0 / 失败 1）、`turn_end.reason.kind`、`final.text`（或 `--json` 用事件流代替）。

**对照硬约束 29**：hook 是 fire-and-forget（永远 exit 0、宿主不回执），所以当年"多一条路"是风险。DSH headless **有回执**，失败看得见 → 不落进 29 的陷阱。
