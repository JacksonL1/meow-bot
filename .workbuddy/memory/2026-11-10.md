- **「找不到 dsh」修好**（S12-4）。报错原文是「PATH 里没有 @deepseek-ai/dsh」，用户转述时
  多打了个斜杠，不是拼接 bug。根因是 `locate()` 只扫 `PATH` 上的 npm 布局，而本机 npm 那份
  **跟着 `C:\nvm4w` 被清空一起没了**（`ls -la` 只剩 `.`/`..`、`which dsh` 空）；dsh 现在只在
  桌面版 `AppData\Local\Programs\DeepSeek Harness` 里。
  - 桌面版入口：`app.asar/dsh/node_modules/@deepseek-ai/dsh-desktop-host/lib/cli.js`，
    用 `DeepSeek Harness.exe` + `ELECTRON_RUN_AS_NODE=1` + `--expose-internals` 跑
    （照抄它自己的 `resources/runtime/bin/node.cmd`）。`--help` 逐条核过，参数与我们用的
    完全一致；`--dump-config` 拿到 `cmg · DeepSeek-V4.1-Flash-1017`（281ms）。
  - 改法：`Launcher` 加 `pre`/`env`/`from`；`command()` 与 `default_model()` 共用 `base()`；
    `locate()` = npm（PATH）→ 桌面版（扫 `%LOCALAPPDATA%\Programs`、`%PROGRAMFILES%`、
    `%PROGRAMFILES(X86)%` 各一层）；留 `CLAWD_DSH_ROOT` 手动指定；失败时把候选目录打进 stderr。
  - **踩到的坑（本轮最值钱）**：第一版桌面版判据是「有 `resources/app.asar` 就算」，
    临时探针当场选中了 **Cherry Studio**（同目录下还有一堆 Electron 应用）——即"拿无关程序
    去跑 dsh 的脚本"。改成「asar 在 **且** exe 名/目录名含 `deepseek`」，并钉成回归测试。
  - 闸门：`cargo test` 68 → **75/0**、`verify:tauri` **134/0**。真机 e2e：2.0 秒拿到「收到」，
    日志 `[say] 出发 … 用 desktop 那份`。
  - **教训**：判据太松的代价不是"找不到"（显式、能报错），是"找错了"（静默、还继续往下执行）。
    自动发现外部程序的判据要能**排除同类应用**；这类代码的验收必须含一次**真机扫描**。
